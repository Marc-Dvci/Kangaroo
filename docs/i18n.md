# Languages

Literacy is not assumed anywhere in this product, and neither is English.

---

## Two different things are localised, and they work differently

This distinction matters, and conflating it is how a project ends up claiming "20 languages" when it
means "20 machine-translated button labels".

### 1. The interface chrome — `ResourceBundle`

Buttons, labels, headings. Translated by people, shipped in the JAR as `.properties` catalogues in
`src/main/resources/i18n/`.

**Shipped and reviewed: English, French.**

That is two, not twelve, and the README says two.

### 2. The clinical action plan — generated by the model

The part a caregiver actually reads and acts on. The system prompt tells the model which language to
write in, by name:

```java
"Write the action plan in %s.".formatted(Messages.languageName(locale))
```

This works for **every language in `Messages.SUPPORTED`**, because it is the model doing the writing,
not a lookup table. It is also the part where quality matters most and is hardest to guarantee — see
the caveats below.

### 3. The offline rung — templates, English only

When no model is available, the narrative comes from templates in `DeterministicEngine`, in English.
Those templates are checked into the repository in full, which makes them the only rung whose output
a clinician can review in advance — and it also means translating them is a bounded, reviewable task
rather than an open-ended one.

**This is the biggest gap in the product's language story**: the configuration most likely to be used
in the field (no signal, no model) is the one with the least language coverage. Fixing it means
translating roughly forty template strings per language, with clinical review. It is the highest-value
next piece of work in this area.

## Adding a language

Adding a catalogue is a translation job, not a code change.

1. Copy `src/main/resources/i18n/kangaroo.properties` to `kangaroo_<tag>.properties`.
2. Translate the values. Leave the keys alone.
3. If the language is not already in `Messages.SUPPORTED`, add it there with its endonym and its
   direction.
4. Rebuild. `Messages.catalogue(locale)` picks it up and `GET /api/i18n/<tag>` serves it.

`.properties` files are read as UTF-8 since Java 9, so write accented and non-Latin characters
directly rather than escaping them.

A missing key **falls back to English and then to the key itself**, never throwing. A clinical
assessment must not fail because a translator has not reached one label yet, and an untranslated key
showing in the interface is the fastest way to get it noticed.

## What a real deployment needs, that this does not have

Being blunt about it, because a health tool that gets its language wrong is a health tool that is
misunderstood at the moment it matters:

- **Native-speaker clinical review, not translation.** "Lethargic" has no good everyday equivalent in
  many languages, and the wrong choice either terrifies a caregiver or fails to convey urgency. This
  needs a clinician who speaks the language, not a translator.
- **Back-translation and reconciliation**, the standard process for clinical instruments.
- **Evaluation of the model's output quality per language.** A model that writes fluent English and
  stilted Hausa will be trusted differently by its two audiences, and the difference will not show up
  in any benchmark run in English. This is unmeasured here.
- **RTL layout testing on real devices.** The stylesheet honours `dir`, but Urdu and Arabic have not
  been tested by anyone who reads them.
- **Voice**, for genuinely non-literate users. The offline speech path is designed for and not built.

Until those exist, the honest description is: **the interface is English and French; the clinical
guidance is model-generated in twelve languages, unreviewed.** The README says exactly that.

## Number and date formatting

Doses, volumes, weights and dates use the caregiver's locale conventions where the platform provides
them. One deliberate exception: **the referral letter renders numbers in a fixed, unambiguous
format**, because it crosses a boundary between a health worker and a receiving facility that may
not share a locale, and a decimal comma read as a thousands separator is a dosing error.
