# The automated demo

A 114-second narrated walk-through that **drives the real application**. One click starts it; you
record the screen.

```
start-demo.bat          Windows
./start-demo.sh         macOS and Linux
```

That builds if needed, starts Kangaroo, and opens the browser on the demo. Press **Start**, and
don't touch anything until the closing card.

---

## What is real, and what is supplied

This matters, because a demo that looks this smooth invites the assumption that it is a video.

**Real** — everything you see computed:

- The WHO IMNCI rule engine and the gradient-boosted head produce every classification.
- The colour pipeline grades every photograph. The Kramer zones on screen were measured.
- The cry analysis measures the fundamental frequency of the clip it is given.
- The chest-motion analysis measures the breathing rate from the trace it is given.
- The Vector API benchmark in beat 6 runs on the machine you are recording on. Those milliseconds
  are that laptop's.
- Every screen is the product's own. There is no demo copy of the interface.

**Supplied** — the sensor input, because a laptop being screen-recorded has no infant in front of
it:

| Fixture | Generated by | Why it is what it is |
|---|---|---|
| The photograph | `makeCapture()` in `demo.js` | A bright near-neutral card border and a skin window at the 0.27–0.73 crop the pipeline uses. Two tones: one the pipeline grades at Kramer zone 0, one it grades as extensive. |
| The cry | `makeCry()` | Ten seconds of harmonic bursts at 520 Hz with breaths between them. The app measures 520 Hz back. |
| The chest-motion trace | `makeMotion()` | Fifteen seconds at 48 breaths a minute — deliberately at odds with the 62 tapped in, so the disagreement the narration describes is the one on screen. |

Those three functions are about sixty lines of arithmetic in `demo.js`. Nothing else is staged, and
no result is hard-coded: change the colorimetry and the demo's jaundice grade changes with it.

## Changing the script

`narration.md` is the source of truth. Edit it, then:

```bash
python demo/generate-voiceover.py --force
./mvnw package
```

The generator writes one MP3 per beat plus `manifest.json` with each clip's **measured** duration,
and the demo paces itself from that manifest — so the choreography re-times itself and cannot drift
out of sync with the words. It also fails loudly if the total leaves the 90–120 seconds the contest
asks for.

```bash
python demo/generate-voiceover.py --list-voices     # other English voices
python demo/generate-voiceover.py --voice en-GB-SoniaNeural --force
```

`edge-tts` is needed only to *build* the narration. The MP3s are committed, so recording the demo
needs neither Python nor a network connection.

## Recording it

- **1920×1080**, browser zoom **100%**, **F11** for full screen. The caption bar is sized for a
  contest page viewed small.
- Use a clean browser profile — no extensions, no bookmarks bar.
- The demo holds on the closing card, so stop recording there rather than trying to catch the end.
- If a beat's audio does not play, the browser withheld autoplay: reload and press Start again
  rather than clicking into the page mid-run.
- The whole thing is idempotent. Reload to run it again.

**Do not** film a real infant. The clinical content is real; the subject should not be a person who
cannot consent. `docs/demo-script.md` is the shot list for a live-action version if you want one.
